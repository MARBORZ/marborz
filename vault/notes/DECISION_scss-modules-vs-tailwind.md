# Решение: CSS Modules + SCSS vs Tailwind
**Дата:** 2026-05-03  
**Связано:** [[../code/ARCHITECTURE]]

---

## INPUT
Нужно выбрать систему стилей для портфолио. Основные кандидаты — Tailwind CSS и CSS Modules с SCSS.

---

## PROCESSING

**Вариант A: Tailwind CSS**
- ✅ Быстрая разработка (utility-first)
- ✅ Встроенная design system (spacing, colors)
- ✅ Популярен в индустрии
- ❌ Классы в JSX загромождают разметку
- ❌ Сложно контролировать нестандартные значения (88px hero, -0.04em letter-spacing)
- ❌ Меньше понимаешь что происходит — просто пишешь классы

**Вариант B: CSS Modules + SCSS**
- ✅ Изоляция стилей — нет глобальных конфликтов
- ✅ Полный контроль над любыми значениями
- ✅ SCSS переменные = design tokens из Pencil напрямую
- ✅ Понимаешь CSS глубже — учишься, а не пользуешься
- ❌ Больше кода нужно писать самому
- ❌ Нет готовой utility системы

**Вариант C: Styled Components / Emotion**
- ✅ CSS-in-JS, co-location со стилями
- ❌ Runtime overhead
- ❌ Сложнее для SSR (если понадобится)
- ❌ Лишняя зависимость

---

## OUTPUT

**Выбор:** Вариант B — CSS Modules + SCSS

**Обоснование:**
1. Дизайн в Pencil использует конкретные значения (88px, -0.04em, #f4f2ed) — они должны жить в токенах, а не в utility классах
2. Цель портфолио — показать понимание архитектуры. CSS Modules с design tokens демонстрируют это лучше чем `className="text-9xl -tracking-widest"`
3. Обучающий момент: понимаешь каждый пиксель, а не просто применяешь классы

**Реализация:**
- `tokens.scss` — все переменные
- `global.scss` — reset + базовые стили
- `[Page].module.scss` — изолированные стили страниц
- `@use '../tokens' as *` — подключение токенов

**Статус:** Done ✅
